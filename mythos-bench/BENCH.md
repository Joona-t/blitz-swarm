# mythos-bench

> Head-to-head harness for blitz-swarm. Runs the same task through `consensus`
> and `mythos` modes, extracts deliverables, executes pytest (plus optional
> hidden adversarial tests), and emits a comparison report.

## Quickstart

```bash
# List available task specs
python mythos-bench/bench.py list

# Run a task in one mode (runs swarm + verifies + logs)
python mythos-bench/bench.py run <task_id> --mode mythos
python mythos-bench/bench.py run <task_id> --mode consensus

# Backfill an already-completed run dir as a result (no re-run)
python mythos-bench/bench.py backfill <task_id> --mode mythos \
  --run-dir output/mythos/<slug>_<ts>/ \
  --cost-usd 1.07 --wall-clock-s 203.2 --rounds 1 --invocations 4 \
  --verifier-verdict pass

# Aggregate results.jsonl into a markdown comparison
python mythos-bench/bench.py compare
```

Results land in `mythos-bench/results/runs.jsonl` (one line per run).
Comparison report lands in `mythos-bench/results/comparison.md`.

## Task spec format

Each `mythos-bench/tasks/<id>.toml` is the full spec:

```toml
[task]
id = "binary_search"
title = "Binary search with explicit loop invariant + tests"
prompt = """The task description handed verbatim to the swarm."""

[deliverables]
files = ["binary_search.py", "test_binary_search.py"]

[verification]
type = "pytest"
target = "test_binary_search.py"
expected_min_pass = 9

# OPTIONAL — verifier-trust probe. Hidden tests not shown to swarm.
[verification.adversarial]
file = "binary_search__adversarial.py"     # under mythos-bench/adversarial/
description = "Hidden tests probing pitfalls the swarm's own tests likely miss."
```

## Verdicts

- `passed` — primary pytest passes; adversarial pytest passes (or not configured).
- `verifier_wrong` — verifier said `pass` but primary or adversarial pytest failed. **The headline failure mode we hunt.**
- `tests_failed` — primary pytest failed. (Verifier correctly didn't pass, or was disabled.)
- `tests_under_min` — fewer tests passed than `expected_min_pass`.
- `adversarial_caught` — primary OK but hidden tests caught a real bug (verifier didn't claim pass).
- `no_deliverable` — couldn't extract code blocks from run output.
- `errored` — orchestrator process exited nonzero.

## Layout

```
mythos-bench/
├── BENCH.md                 # this file
├── bench.py                 # CLI
├── lib.py                   # extraction, pytest runner, result io
├── tasks/                   # task specs (visible to swarm)
├── adversarial/             # hidden test files (NOT visible to swarm)
├── artifacts/               # extracted deliverables + per-run logs
└── results/
    ├── runs.jsonl           # append-only result log
    └── comparison.md        # generated by `bench.py compare`
```

## Verifier-trust probes — how to design them

A trust probe should:
1. Have a prompt that doesn't enumerate every adversarial edge case.
2. Have a hidden test file under `adversarial/` checking pitfalls the swarm's
   own tests are likely to miss.
3. Use deterministic seeds — flaky adversarial tests aren't probes, they're noise.

If `verifier_verdict == "pass"` and `adversarial_pytest.failed > 0`, the harness
emits `verdict: verifier_wrong` — that's the smoking gun.

## Caveats

- Consensus mode wasn't designed for code-as-deliverable tasks. The fairer
  reading of head-to-head results: even when forced into a code task,
  consensus mode pivots awkwardly (researchers truncate code blocks → the
  synthesizer must backfill); Mythos's planner-executor-verifier hierarchy
  is the right shape.
- The bench is single-machine. No parallelism across tasks (yet).
- Cost telemetry depends on the orchestrator printing `Cost:` and `wall:`
  lines — if those formats change, bump `parse_metrics_from_log` in `lib.py`.
- Adversarial tests are **honor-system hidden** — they live in the repo, the
  swarm could theoretically grep for them. The harness contract is "we don't
  hand the file to the swarm"; if Mythos ever gets shell access, this changes.
